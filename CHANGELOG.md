# Changelog

Every release of @latro/ops-ui, newest first (spec §4.3). Each section is `## X.Y.Z — date` with
`Added:` / `Changed:` / `Fixed:` / `Visible:` / `Breaking:` / `Upgrade steps:` lines; a major
names every pixel change (`Visible:`, per component) and the exact steps per app
(`Upgrade steps:`). The sync prints the sections between an app's version and the new one.

## 1.3.0 — 2026-10-01
Added: styles/preflight-scoped.css (PrefabOps restyle plan M1 / G19, library spec §13.2): Tailwind's preflight (tailwindcss 4.3.3, rule for rule, every declaration verbatim) applied only to an element of class ops-ui-root and everything inside it, each selector scoped with a zero-specificity :where(), so a page whose legacy CSS predates Tailwind can host kit islands without the global reset. Import it in layer(base) above the legacy layer and instead of the global preflight; an app that imports tailwindcss already has the reset and needs nothing. Generated by gallery/preflight-scope.mjs (tests/preflight-scoped.test.ts compiles both and compares rule for rule).
Added: the stacking variables (M1 / G18, restyle plan §5.5) --ops-z-toast (default 60, the toast viewport), --ops-z-calendar (50, DateInput's floating calendar), --ops-z-menu (40, RowMenu's and AppSwitcher's menus) and --ops-z-sheet (40, Sheet's overlay): each layer's z-index is now var(--ops-z-…,<its 1.2 value>), so an app that sets nothing stacks exactly as before (tests/touch-and-stacking.test.tsx proves each line is the 1.2.0 line with the literal swapped for the variable). TOKENS.md → Layout variables (5).
Added: the opt-in touch floor (M2 / G2): with data-ops-touch on an ancestor, on (hover: none) and (pointer: coarse), Button (and ButtonLink, ExternalButtonLink, FileLink), IconButton, Input, Select, Combobox, DateInput, Segmented's options and the RowMenu trigger are at least 44px tall (icon-only controls 44px wide too) and Input, Select, Textarea, Combobox and DateInput draw 16px text. lib/touch.ts: TOUCH_FLOOR (the three classes), ControlSize, CONTROL_SIZE_CLASS. Without the attribute the classes paint nothing.
Added: size="lg" (M2 / G2): Button, ButtonLink, ExternalButtonLink h-12 px-4 text-base with a 16px glyph; Input, Select (size: "md" | "lg" | number), Combobox and DateInput (size: "md" | "lg") h-12 with 16px text at every width.
Added: IconButton (M2 / G4, components/button.tsx): required label → aria-label + title, icon (ActionIconName, always drawn), square sm (32px) / md (36px) / lg (48px), variant (any Button variant, default ghost), type defaults to "button", read-only aware like Button (hidden in a read-only scope unless readOnlySafe), honours the touch floor.
Added: ActionIcon glyphs sparkle (an action the AI does: draft, read a scan) and mail (compose an e-mail) (M2 / G17).
Added: DESIGN.md → Actions (lg, IconButton), Responsive (the touch floor; islands and stacking); 6 stories (card--island-on-a-legacy-page, button--large, button--icon-buttons, button--touch-floor, field--large, action-icon--added-in-1-3), new baselines only. The gallery's own reset is gallery/app/preflight-global.css (the same transform, every element unless html[data-ops-preflight=scoped], which only the island story sets); every existing baseline is unchanged.
Not in 1.3.0: G3 (Dialog as a bottom sheet on phones), listed for M2 in the restyle plan, shipped in 1.0.0 (every Dialog below sm, spec §12.4 option 1), so there is no presentation prop. M3 (Input prefix / suffix, YearInput, RowMenu trigger + sections) is 1.4.0.
Changed: the class lists of the components above gain the floor classes (and the z-index classes read the variables): DOM attributes only, 0 changed pixels on every existing baseline.
Compatible: buttonVariants - its size gains "lg"; sm and md (and no size) produce the same classes as in 1.2 plus the floor class, which paints nothing without data-ops-touch.
Compatible: Input - size widens from the HTML attribute (number) to "md" | "lg" | number: a number is still passed through as the size attribute, no size renders the 1.2 classes plus the floor classes.
Compatible: Select - as Input: size widens to "md" | "lg" | number, a number stays the HTML size attribute.
Compatible: Combobox - gains an optional size ("md" | "lg"); without it the input renders as in 1.2 (plus the floor classes).
Compatible: DateInput - gains an optional size ("md" | "lg"); without it the field renders as in 1.2 (plus the floor classes).
Compatible: ActionIconName - widened by "sparkle" and "mail"; every 1.2 name draws the same path.
Compatible: OPS_UI_VERSION - the 1.2.0 release wrote src/version.ts, so the declared literal moves from "1.1.0" to "1.2.0" in the surface; the constant's type and meaning are unchanged and no component reads it.
Reviewed: touch - lib/touch.ts carries the floor's media query (hover: none) and (pointer: coarse); it applies only under data-ops-touch, which no existing app sets, so every existing control looks the same on hover, focus and touch (the 375-touch shots of every existing story are unchanged).
Reviewed: Button - the base classes moved into an array beside the floor class, the hover: / focus-visible: classes are unchanged word for word; lg and IconButton reuse them.
Upgrade steps: node scripts/sync-ops-ui.mjs --version 1.3.0 (no new component file, so no new wrapper; --write-wrappers never rewrites an existing one, so an app that wants IconButton adds it to the export list of its src/components/ui/button.tsx wrapper). Nothing else: the floor and the stacking variables are opt-in, preflight-scoped.css is imported only by an app hosting islands (PrefabOps from P2). The new stories are new /dev/kit routes in G2; every existing route stays at 0 changed pixels.

## 1.0.0 — 2026-10-01
Added: the kit, a pure extraction: the 35 kit files of FinaOps (fina-ops 80828fc, src/components/ui, with button, date-input, dialog and glance-card re-imported from fina-ops 19aad88 after both apps' kits were aligned, spec §12.4 option 1) as src/components/, with the §7 and §9 changes only; from Workforce Ops (workforce-ops cea4928) navigation/ (trail, history, NavTrail) and lib/ (cn, fmt, text, dates, date-input, use-dismissable, floating-place, sheet-motion); lib/months.ts from FinaOps.
Added: config/ (OpsUiProvider, useOpsUi, OpsUiStrings, EN_STRINGS; ReadOnlyScope, useReadOnlyScope), types.ts, version.ts.
Added: styles/tokens.css (the @theme contract, brand values through --brand-* variables), kit.css, base.css, app-feel.css; TOKENS.md (the contract), DESIGN.md (the shared doctrine).
Added: stories for every component (src/stories, StoryHost for an app's /dev/kit view).
Added: scripts/sync-ops-ui.mjs and its declarations scripts/sync-ops-ui.d.mts.
Browser floor: color-mix() (Safari 16.2+, Chrome 111+, Firefox 113+). The brand tokens are var() indirections, so for a browser without color-mix() Tailwind cannot precompute an opacity-modified brand colour (bg-primary/10, ring-primary/25, bg-ink/40, the external Monogram's bg-external/10): its fallback there is the opaque token, where the apps' literal tokens degraded to a translucent tint. Tailwind v4's own floor (Safari 16.4, Chrome 111, Firefox 128) already lies above it, so no browser either app supports sees a difference.
Visible: none. 1.0.0 is a pure extraction: every story renders as the FinaOps kit (fina-ops 19aad88) it was taken from, which equals Workforce Ops' (bottom-sheet dialogs below sm, the touch calendar sheet, ExternalButtonLink); the extraction proof is docs/extraction-proof-1.0.0.md in the ops-ui repository (spec §12.1 L6).
Upgrade steps: none (the first release); each app adopts it through the steps of spec §12.2 (FinaOps F0-F7) and §12.3 (Workforce Ops W0-W8). Its globals.css scans the vendor folder and nothing else the adoption puts in the app tree (spec §8.4): the @source line plus one @source not line each for the vendored .md files, scripts/sync-ops-ui.*, ops-ui.config.json and ops-ui.lock.json (Tailwind's automatic detection reads root JSON, and a config lists token names), so neither a docs-only release nor a config edit changes the app's CSS or its token dump. Once globals.css imports the library tokens, the sync refuses an app @theme that declares anything but its listed extensions, a rule that sets a library token or a brand variable outside brand.css, and a missing brand.css import (spec §8.5 check 7).
